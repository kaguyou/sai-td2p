# 議事録: AS5812-54T に SONiC を入れる (2026-11-13)

目的: ホームラボ(本番ではない)で BGP/EVPN-VXLAN と GitOps による設定管理をやる。手元のスイッチに SONiC を入れたい。

## 決まったこと

1. **コミュニティ版 SONiC はこの機体では使えない**と確定。OS は入るが、ポートが動かない(下の「確認した事実」)。
   - SONiC の版を変えても直らない(どの版も同じ Broadcom SAI の系統を使うため)。「202411 版で入れ直す」案は取り下げ。
   - Edgecore 公式の SONiC イメージ(54T 用)を再び頼むことはしない(2026-06 にサポートから「提供しない」と回答済み、EC Ticket #49798)。
2. **次の方向は A(別の NOS)か B(54X 用 SAI の流用)**。本人が C(機体を替える)と D(仮想環境)を外した。
   - Claude の見解: **A の PicOS**。54T 専用のページが今の PicOS 4.4 / 4.5 のドキュメントにあり、現役で対応しているのはこれだけ。B は 54X のイメージを入手するのに Edgecore との契約が要るうえ、移植の手間が大きい。
   - 最終決定は、Muse AI の調査結果を見てから。

## 確認した事実

### 機体
| 項目 | 値 |
|---|---|
| 本体 | Edgecore (Accton) AS5812-54T、型番 5812-54T-O-AC-F |
| 部品番号 / シリアル番号 | FP1ZZ5654031A / 581254T1721031 |
| 基本の MAC アドレス | A8:2B:B5:3A:3E:8E |
| 製造日 | 2017-06-27 |
| ONIE | 2015.11.00.01、platform `x86_64-accton_as5812_54t-r0` |
| ASIC | Broadcom Trident II+ BCM56864_A1(PCI `14e4:b864` rev 02) |
| ポート | 10GBASE-T ×48 + 40G QSFP+ ×6 |

### SONiC 202505 を入れた結果
- インストールは成功(17:29 取得 → 17:33 再起動 → 起動・ログイン可)。
  - 版: `SONiC.202505.1238526-ff3c0c9f6`、HwSKU `Accton-AS5812-54T`、カーネル 6.1.0-29-2
  - プラットフォームのドライバ `sonic-platform-accton-as5812-54t_1.1` も正常に入った。
- **syncd が初期化で失敗し、ポートが一切使えない**:
  ```
  BDE dev 0 (PCI), Dev 0xb864, Rev 0x02, Chip BCM56864_A1, Driver BCM56860_A0
  soc_attach: unit 0 has no driver (device 0xb864 rev 0x02)
  SAI_API_SWITCH:platformInit:1653 ERROR: SOC unit 0 attach failed
  ```
- 原因: SAI(libsaibcm 13.2.1.36)は入っていて読み込まれている。ただ、その中の Broadcom SDK に Trident2+(BCM56860 系)のドライバが含まれていない。
- できないこと: 前面 54 ポートを使うことは全部(L2/L3 の転送、VLAN、前面ポートでの BGP、EVPN、LACP)。
- できること: 起動、コンソールでのログイン、コマンド。管理ポートでの SSH と、ファン・電源・温度の監視は「たぶんできる」(未確認)。

### 他の NOS の対応状況(Web で調べた範囲、未検証)
- **PicOS**: データシートに 2.8.0 以降で対応と記載。PicOS 4.4 / 4.5 のドキュメントに 54T のページがある。
- **OcNOS**: 54T への対応は DC 1.3.8〜1.3.9 までで、販売終了。7.0 の対応表には載っていない。
- **Cumulus Linux**: 54T 用のライセンス SKU はある。Broadcom 版はすでに開発が終わっていて、入手できるかは不明。

## 未決のまま残っていること

- A と B のどちらにするか(Muse AI の調査待ち)。
- PicOS の場合: ライセンスの費用(試用版があるか)、Trident2+ で EVPN-VXLAN が使えるか、GitOps(自動化の API や Ansible)との相性。
  - **実際にお金を払うかは本人が決める。** Claude は申し込みをしない。
- B の場合: 54X 用の SAI を手に入れる方法。.deb を差し替えるだけで済むか、10GBASE-T の PHY の初期化まで手を入れる必要があるか。

## 経緯(時系列)

1. 「コンソールの API を使えるか」→ Anthropic Console の API キーは Claude Code で使える(`/login` で Console を選ぶか、`ANTHROPIC_API_KEY` を設定)と回答。今の設定はサブスクのまま。
2. 「接続しているスイッチを見て」→ USB シリアル経由で ONIE のコンソールに入り、機種を特定。ONIE がインストーラを探してループしていた。管理ポートはリンクダウン。
3. SONiC の対応を調べ、202505 のビルド済みイメージをダウンロード。
4. LAN ケーブルを1回差し直してリンクが来た。PC から HTTP で配信して `onie-nos-install` で書き込み。
5. 本人が以前の調査メモ(Edgecore の回答、`0xb864` で失敗)を共有。A〜D の案を出し、本人が A か B に絞った。
6. 起動後の syncd ログで、`0xb864` 非対応をこの機体でも確認。
7. Muse AI 用の調査プロンプトを作成(下)。

## 付録: Muse AI 用の調査プロンプト

```
# 調査依頼: Edgecore AS5812-54T でデータプレーンが動く NOS を選ぶための事実確認

## 前提（確認済み。再調査・再提案は不要）
- 機体: Edgecore (Accton) AS5812-54T（10GBASE-T ×48 + 40G QSFP+ ×6）
  ONIE platform: x86_64-accton_as5812_54t-r0 / ONIE 2015.11.00.01
- ASIC: Broadcom Trident II+ BCM56864_A1（PCI 14e4:b864 rev 02）
- コミュニティ版 SONiC 202505（Broadcom ビルド）は入るが、syncd が
  "soc_attach: unit 0 has no driver (device 0xb864 rev 0x02)" で失敗し、データプレーンが動かない
- Edgecore サポート回答（2026-06）: 54T は Edgecore SONiC の対応表に載っておらず、イメージは提供されない。54X（同じ ASIC）は対応
- 用途: 個人のホームラボ（本番ではない）。目的は BGP/EVPN-VXLAN と GitOps による設定管理

## 調べてほしいこと

### A. 別の NOS を 54T に入れる
1. PicOS（Pica8）
   - 54T に対応している最新版はどれか（4.4 / 4.5 のドキュメントに 54T のページがあるのは確認済み）
   - ライセンスの形態と価格（個人で買えるか、試用版や評価版はあるか、ポート数ごとの課金か）。イメージはどこから入手するか
   - Trident2+ / 54T で EVPN-VXLAN（L2VNI、L3VNI / 対称 IRB）が使えるか。機種ごとの制限
   - 自動化の手段（NETCONF / gNMI / REST / Ansible collection）と、テキスト設定を Git で管理する実例
2. ほかの候補が今も現実的か（54T 対応・入手性・費用・EVPN）
   - Cumulus Linux 4.x の Broadcom 版（イメージとライセンスを今入手できるか）
   - OcNOS（54T 対応は DC 1.3.8〜1.3.9 で販売終了らしい。現行版で使えるか）
   - そのほか、54T が動く NOS があれば（OpenSwitch、Big Switch 系、ONL + 何か など）

### B. 54X 用の SONiC / SAI を 54T に流用する
- AS5812-54X 向けの Edgecore SONiC（または同梱の libsaibcm）を 54T で動かした、または動かそうとした事例
- Broadcom SAI 自体が BCM56864 に対応している版（コミュニティ版で TD2+ が外れた時期と理由）
- 54T と 54X の違いで移植の障害になるもの（10GBASE-T PHY の型番と初期化、ポートの割り当て、CPLD）

## 出力の形
- 候補ごとに「54T で動く／動かない／不明」の判定、その根拠（一次情報の URL と、該当する記述の引用）、費用、EVPN 対応、GitOps との相性を表にまとめる
- 「ドキュメントで確認した事実」と「推測や二次情報」をはっきり分ける。わからないことは「不明」と書く
- 情報源は英語の一次情報（ベンダーのドキュメント、HCL、リリースノート、GitHub、メーリングリスト）を優先し、日付を書く
- 最後に、ホームラボで BGP/EVPN と GitOps を実現する目的に照らして、どれが最も現実的かを根拠付きで1つ挙げる
```
