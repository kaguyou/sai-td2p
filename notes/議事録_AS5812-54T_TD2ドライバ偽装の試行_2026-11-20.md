# 議事録: AS5812-54T に SONiC コミュニティ版 SAI を「少しいじって」動かせるか (2026-11-20)

## 結論
- **不可。** コミュニティ版 libsaibcm 13.2.1.36 (SDK 6.5.32-SP2) には Trident2+ (BCM56860 系) のチップ定義が入っていない。
  デバイス ID を Trident2 (BCM56850) に偽装すると SDK は attach まで通るが、Trident2 と Trident2+ で TOP ブロック等のレジスタ番地が別物なので、
  初期化の最初のレジスタ群で S-channel タイムアウトになる。レジスタ表そのものが無いため、バイナリの数バイト書き換えでは直らない。

## やったこと
1. 現状確認: `soc_attach: unit 0 has no driver (device 0xb864)`。libsai に `soc_driver_bcm56850_a0` はあるが `soc_driver_bcm56860_a0` は無い。
2. LD_PRELOAD の ioctl 横取りライブラリ (`~/homelab/as5812-bdeshim/bdeshim.c`) を作成。
   /dev/linux-user-bde の LUBDE_GET_DEVICE (nr=2) の返値 d0 を 0xb864→0xb850 に書き換える。
   syncd コンテナの `/usr/bin/syncd_start.sh` に LD_PRELOAD を差し込んで試行。
3. 結果: `BDE dev 0 (PCI), Dev 0xb850, Rev 0x02, Chip BCM56850_A1, Driver BCM56850_A0` で attach 成功。
   続く `init soc` が `_soc_cmicm_schan_op: operation (0xb) timed out` で失敗。
4. /dev/mem で CMIC を直読み (BAR0 0xdfe00000)。CMC0 SCHAN_CTRL=0x00400000 (SBUS タイムアウト)、
   最後のメッセージ: opcode 0x0b(READ_REGISTER) dst_blk=57(TOP) addr=0x02042400。
5. OpenBCM (sdk-6.5.27, `~/homelab/openbcm-src/out/`) の生成レジスタ表で突合:
   - TOP_XG_PLL0_CTRL_1: TD2 0x2042400 / TD2+ 0x2031200
   - TOP_SOFT_RESET_REG: TD2 0x2030400 / TD2+ 0x2030100
   - TOP_MISC_CONTROL:   TD2 0x2031400 / TD2+ 0x2030500
   - TD2+ 専用の TOP レジスタ定義 114 本、MMU (THDI 等) にも差分あり。
   - ブロック番号・SBUS リングマップは両者同一 (TOP=57, SER=58, MMU=3, IP=1, EP=2)。差は AVS(59) の有無のみ。

## 片付け
- syncd_start.sh を元に戻し、bdeshim.so とログ、/tmp の走査結果を機体から削除。SAI ログレベルも既定に戻した。
- swss/syncd は停止状態で放置 (起動しても失敗ループになるだけ)。再起動すれば元の起動シーケンスに戻る。
- 時刻は手動で合わせた (RTC 無しの機体なので電源を切ると狂う)。NTP サーバ設定 (NICT) は config に保存済みだが管理ポート未接続。

## 追記 (2026-11-20 夜): OpenBCM 自前ビルドで ASIC 起動に成功
- 本人決定「改造して動かす」→ OpenBCM sdk-6.5.27 を BCM56860 有効(Make.config の DEPRECATED から ESW へ戻す)でビルド。
  - 落とし穴: DEBUG_ASSERTS=FALSE(NDEBUG)にすると user BDE の `assert(ioctl(...))` が消えて 0 台になる。assert 有効が必須。
  - src/Makefile の `override MAKEFLAGS += TARGET=` が -j を落とす。`MAKEOVERRIDES :=` + Make.subdirs で TARGET 明示渡しに修正。
  - 6.5.26 はヘッダ欠落で使えない。
- 機体: /dev/linux-user-bde を mknod c 126 0 で作成、swss/syncd 停止、~/bcm/{bcm.user,config.bcm}。
- 結果: Chip BCM56864_A1 / Driver BCM56860_A0 で attach、init soc/misc/mmu/bcm 成功、BCM84858 PHY 48 本初期化、xe0-71 認識。
- 10G ループ試験(前面 2↔3、2↔36): リンク 10G、tx で双方向にフレーム通過(同一 VLAN ループでブロードキャスト増殖=ラインレート転送)、L2 学習確認。
- 1G(PC 直結、ポート 1): オートネゴで 1G リンク、内部 SerDes が 10G のまま残りフレームが流れない。`port 1 if=sgmii` を再適用すると流れ、PC の MAC を学習。要調査(phy8481 link_up の notify 経路)。
- CPU からの tx は速度変更後に `dv_vcnt = 0` で失敗する副作用あり(初期状態では成功)。
- ファン: as5812_54t_fan/cpld/psu ドライバが kernel 6.1 で probe -22。`i2cset -y 1 0x60 0x0d <percent/5>` で CPLD 直接制御(0x04=20%)。accton_as5812_monitor.py は kill。温度は CPU 36C/基板 30C 前後で問題なし。
- ネットワーク: 学内有線は機器間遮断。PC↔MGMT 直結(NM プロファイル sonic-mgmt 192.168.0.1、機体 eth0 192.168.0.2 保存済、IPv6 fe80::aa2b:b5ff:fe3a:3e8e%enp2s0)。
- 次: SDK を -fPIC で再ビルド(進行中)→ sonic-sairedis vslib を土台に Trident2+ 実機クラスを追加した libsai を作り、docker-syncd-brcm の libsai.so.1 を差し替える。ALPM 有効版 bcm.user は ~/homelab/as5812-bdeshim/bin/bcm.user-alpm。

## 追記 (2026-11-20 22:20): SONiC が自前 SAI で起動
- 並列 5 本(A1 hwbcm C 層 / A2 SAI 中核 / A3 L3 / A4 VXLAN / A5 配備)で ~/homelab/sai-td2p と sonic-sairedis/vslib に実装。設計書 ~/homelab/sai-td2p/DESIGN.md。
- 落とし穴と解決:
  - KNET: SONiC のカーネルモジュールは KCOM_VERSION 18、KCOM_NETIF_MAX 1056、KCOM_FILTER_MAX 1025。SDK 側 include/kcom.h を SONiC 版(saibcm-modules/include/kcom.h)に差し替え、上限値も合わせた(kcom.h.orig-6.5.27 に原本)。
  - libtool は共有ライブラリのリンクで素の .a を黙って捨てる → LIBS に -Wl,<archive> で渡す(deploy/build.sh)。
  - 診断シェルのコマンド表: bslmgmt_init/diag_init → sysconf → cmdlist_init/command_mode_set(ESW_CMD_MODE) が必要。
  - 10GBASE-T PHY(BCM84858)の 10G はオートネゴ必須。bcm_port_autoneg_set(1) のみで advert は触らない。
- 結果: deploy/install.sh で syncd コンテナの /usr/lib/libsai.so.1 → libsaivs.so.0.0.0(自前、136MB)に差し替え(純正は libsai.so.1.vendor に保存)、sai.profile に SAI_VS_SWITCH_TYPE=SAI_VS_SWITCH_TYPE_BCM56860HW 等を追加、lanemap.ini 生成。
  swss/syncd 起動 → orchagent 稼働、show interfaces status に Ethernet0-71(10G, admin up)、KNET netdev 72 本(driver bcm-knet)。
- 巻き戻し: deploy/rollback.sh。未検証: リンク状態反映、L2 疎通、hostif 経由の疎通、L3、VXLAN。
