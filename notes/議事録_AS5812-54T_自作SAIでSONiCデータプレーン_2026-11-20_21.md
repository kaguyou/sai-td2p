## 実機で見つけて直した不具合(いずれも自作 SAI 側の初期化漏れ)
1. **全ポートの STP 状態が Disable**(`init bcm` 後の既定)。入口で全フレーム破棄 → 送信は通るのに受信 0 の症状。常に FORWARD を強制(init / admin up / VLAN 作成 / メンバ追加)。
2. **KNET 受信フレームに PVID のタグが残る**。Linux が無視し ARP に応答しない。Broadcom 純正と同じ 2 フィルタ構成(PVID 一致で STRIP_TAG / それ以外はタグ保持)にし、PVID 変更時に作り直す。
3. **CPU ポートが VLAN メンバでない**。自分宛 IP の L3→CPU コピーが CPU ポートの出口 VLAN チェックで落ちる(cpu0 の TDBGC3 が ping と同率で増え、KNET DMA には届かない)。全 VLAN に CPU を追加、削除は拒否。
4. 1G リンク時の SGMII 再適用: 「SONiC の希望速度」でなく「交渉後の実速度」で判定。再適用でリンクが一度落ちるため、1 接続につき 1 回・自分のバウンスは無視・10 秒レート制限(無限フラップの修正)。
5. ASIC が学習した MAC が SONiC に上がらない: C++ 側が hwbcm の L2 コールバックを登録していなかった。登録し、SDK スレッド→イベントキュー→vslib 既存の学習経路で FDB_EVENT を送出。
6. 既定 VRF(oid 0x300000000)の未対応警告: 基底クラスが先に作るため対応表に無かった。既定 VR を bcm vrf 0 に明示対応。
7. VXLAN 上で学習した MAC は VFI イベント(vid>4095, port=VP)で届く → 実 VLAN/ポートへ変換するフックを追加(EVPN type-2 広告に必要)。
8. (未修正・A4 へ依頼中)リモート MAC の投入が「deferred (vp -2147483647)」で永久保留: VP gport 0x80000001 を signed int で負判定。

## 診断の決め手になった道具と手順
- **診断シェル socket**: syncd 内 `/var/run/hwbcm/shell.sock` に 1 行 1 コマンド。PC から `deploy/bsh "ps"`、シリアルからは docker exec の python ワンライナー。`ps` / `stg show` / `vlan show` / `l2 show` / `l3 defip show` / `l3 egress show` / `show c <port>` / `show c cpu0` / `getreg` / `d chg <table>` が有効。1G リンク時はポート名が xe→ge に変わる(例: ge0 = 論理 47)。
- 受信経路の切り分け順: ポートの RX カウンタ(RPKT/RIPC4) → cpu0 の TDBGC/MC_PERQ → `/proc/bcm/knet/stats`(Rx0, filter hits) → netdev の RX → tcpdump。今回は「cpu0 の TDBGC3 は増えるが KNET DMA に届かない」で CPU の VLAN 非所属に到達。
- 疑似 EVPN の投入: JSON を `docker exec -i swss sh -c 'cat > /tmp/x.json'` で書き、`docker exec swss swssconfig /tmp/x.json`(docker cp では swssconfig が開けなかった)。
- PC 側の BGP ピア: rootless podman の `quay.io/frrouting/frr:10.4.1`、`--network host --cap-add NET_ADMIN,NET_RAW,SYS_ADMIN`、bgpd は `-p 1179`(179 を bind できないため。スイッチ側 179 へ能動接続で張れる)。設定は scratchpad の frr/。
- スイッチからの ping は既定で Loopback0(10.1.0.1)が送信元になり PC に戻り経路がない → `-I` で送信元指定。
